# Spark of Chaos — Static Website Redesign

**Date:** 2026-09-06
**Status:** Approved design, ready for implementation planning
**Repo:** `git@github.com:Spark-of-Chaos/spark-of-chaos.github.io.git`
**Branch:** `www` (orphan, clean history)

---

## 1. Context

Spark of Chaos is a game studio in Nijmegen, The Netherlands, focused on simulation
games. Two titles: **Kabonk!** (released, on Steam) and **Fernweh** (camping tycoon, in
development).

The live site at `sparkofchaos.com` is generated by a Laravel + Backstage CMS application
living on the `gh-pages` branch, which renders static HTML into
`public/static/sparkofchaos.com/` and deploys that directory to GitHub Pages. An older
plain-HTML/Tailwind version sits on `main` and `static-page`.

This project replaces that with a hand-authored static site — plain HTML, CSS and JS, no
build step and no dependencies — that Claude can manage directly.

### Goals

1. A site Claude can add to, edit and remove content from with no build tooling.
2. A fresh design that unifies the currently split visual language (bright rainbow home
   vs. black game pages).
3. Room for a blog/updates stream, since Fernweh is in active development.
4. Documented style guidelines so the site does not drift as it grows.

### Non-goals

- Any CMS, admin UI, or server-side component.
- Any framework, bundler, package manager or CDN dependency.
- Migrating the Laravel application. It stays on `gh-pages` as a backup.

---

## 2. Constraints

These are hard. They are the reason the site stays manageable, and they are restated in
`CLAUDE.md`.

| Constraint | Rationale |
|---|---|
| No build step | What is committed is exactly what deploys. No stale-artifact class of bug. |
| No runtime dependencies, no CDN | Site cannot break because a third party changed or vanished. |
| No frameworks | Any future Claude session can read one CSS file and one JS file in full. |
| Self-hosted fonts and assets | No third-party requests; faster first paint; no external tracking. |
| Progressive enhancement | Every page renders complete and readable with JS disabled. |
| One stylesheet, one script | Predictable place to make a change. |

## 3. Branch and deployment

### Branch strategy

- **`www`** — new orphan branch. Created with `git checkout --orphan`, so it carries none
  of the Laravel history. This becomes the default branch once the user approves.
- **`gh-pages`** — current default, the Laravel/Backstage application. Untouched. Backup.
- **`main`**, **`static-page`** — the older static site. Untouched. Backup.

The user sets the default branch manually when ready. This spec does not change it.

### Deployment

`.github/workflows/deploy.yml` — on push to `www` and on `workflow_dispatch`:

1. `actions/checkout@v4`
2. `actions/configure-pages@v5`
3. `actions/upload-pages-artifact@v3` with `path: '.'`
4. `actions/deploy-pages@v4`

Permissions `contents: read`, `pages: write`, `id-token: write`; concurrency group
`pages` with `cancel-in-progress: false`, matching the existing workflow's conventions.

The repository root **is** the site. `CLAUDE.md`, `STYLE.md`, `tools/` and `docs/` ship
alongside it; the repository is public, so this exposes nothing sensitive and keeps the
deploy trivially predictable.

`CNAME` contains `sparkofchaos.com`, carried over from `main`. `.nojekyll` prevents
GitHub's Jekyll pass from mangling paths.

**Note for the user:** the existing workflow on `gh-pages` triggers only on pushes to
`gh-pages`, so it will not compete with this one. Once `www` is default and verified, that
workflow is worth disabling to remove any chance of a double deploy.

- Lowercase, hyphen-separated. No spaces, no exclamation marks in filenames — the current

## 5. Design system

### 5.1 Direction

Dark arcade, game-first. One consistent dark canvas across the entire site. The spark
gradient — currently the home page background — becomes accent-only: logo bloom, heading
fills, hairlines, focus rings. Games get full-bleed showcase strips carrying their own
art and palette. Studio, team and contact sit calmly at the bottom.

### 5.2 Tokens

Declared once on `:root` at the top of `site.css`. Nothing below hardcodes a colour.

**Canvas**

| Token | Value | Use |
|---|---|---|
| `--ink-950` | `#06070c` | page background |
| `--ink-900` | `#0b0e16` | alternating bands |
| `--ink-800` | `#121724` | cards |
| `--ink-700` | `#1b2233` | raised surfaces, hover |
| `--line` | `rgba(255,255,255,.09)` | hairlines, card borders |

**Text**

| Token | Value | Use |
|---|---|---|
| `--text` | `#e9edf6` | body |
| `--text-dim` | `#98a2b8` | secondary, meta, captions |

`--text` on `--ink-950` is ~16:1 contrast; `--text-dim` on `--ink-950` is ~7:1. Both clear
WCAG AA comfortably.

**Spark ramp** — the existing ember particle colours, preserved exactly:

```
--spark-1 #0f4170   --spark-2 #214846   --spark-3 #a9c464   --spark-4 #f8322b
--spark-5 #f28c33   --spark-6 #fac453   --spark-7 #f4f3be
--spark-gradient: linear-gradient(135deg, var(--spark-1) … var(--spark-7))
```

**Accent**

| Token | Value | Use |
|---|---|---|
| `--accent` | `#f38f55` | primary interactive; also `<meta name="theme-color">` |
| `--accent-2` | `#f0ba4c` | gradient partner, hover |

**Per-game palettes.** Set as local overrides on a scope class, so one component set
serves both games and any future third game:

```css
.kabonk  { --game-accent:#ff00ff; --game-accent-2:#a3e0fc; --game-bg:#14030f; }
.fernweh { --game-accent:#f0a45a; --game-accent-2:#7fb98a; --game-bg:#0b120e; }
```

Kabonk!'s values are its existing in-game magenta and ice blue. Fernweh's are new —
campfire amber and pine — chosen to read as warm dusk against Kabonk!'s neon.

**Space** — 4px base: `--space-1` `.25rem` through `--space-12` `6rem`.
**Radius** — `--radius-sm` `4px`, `--radius` `8px`, `--radius-lg` `16px`.
**Shadow** — `--shadow` and `--shadow-lg`, plus `--glow` for accent bloom.

### 5.3 Typography

Both self-hosted as woff2, latin subset, `font-display: swap`.

- **Display** — Bruno Ace SC 400. Wordmark, `h1`, section headings. Token `--font-display`.
- **Body** — Exo 2, variable weight axis 300–900. Token `--font-body`.

`BlackOpsOne-Regular.ttf` exists in the old repo but is unreferenced. Dropped.

Fluid scale via `clamp()`, so no per-breakpoint font sizing:

```
--step--1  clamp(.833rem, .79rem + .2vw,  .938rem)   meta, captions
--step-0   clamp(1rem,    .95rem + .25vw, 1.125rem)  body
--step-1   clamp(1.25rem, 1.15rem + .5vw, 1.5rem)    lead, h3
--step-2   clamp(1.6rem,  1.4rem + 1vw,   2.25rem)   h2
--step-3   clamp(2rem,    1.6rem + 2vw,   3.25rem)   h1
--step-4   clamp(2.75rem, 2rem + 3.75vw,  5.5rem)    hero wordmark
```

Body line-height `1.65`; headings `1.15`; prose measure capped at `68ch`.

### 5.4 Motion

Every decorative animation sits behind:

```css
@media (prefers-reduced-motion: reduce) { /* freeze to a static, intentional state */ }
```

The reduced-motion state is a design state, not a broken one. Transitions are ≤ 250ms,
`ease-out`. No scroll-hijacking, no parallax, no entrance animations that delay content.

## 6. Page specifications

### 6.1 Shared chrome

**Skip link** — first focusable element, jumps to `#main`.

**Nav** — sticky, translucent, `backdrop-filter: blur()`, hairline bottom border.
Logo (links home) · `Games` · `Updates` · `Studio` · Discord icon.

The current nav has **no mobile menu** and collapses badly on narrow viewports. This one
gets a hamburger below `48rem` — a `<button aria-expanded aria-controls>` toggling a
panel, closing on Esc, on outside click, and on link activation, returning focus to the
button.

**Footer** — the fire canvas ("Made with 🔥 by Spark of Chaos"), studio line, social row,
copyright. Canvas pauses when offscreen (`IntersectionObserver`) and does not start at all
under reduced motion, falling back to a static flame glyph.

### 6.2 Home — `index.html`

   itself: a CSS-only *spark bloom* — layered radial gradients in the ramp colours behind

   spark ramp as `background-clip: text`. Tagline: *"We build simulation games and
   experiences people enjoy."* CTAs: `Our games` (primary) · `Join our Discord` (ghost).

LinkedIn, external-link), each `aria-hidden` with an adjacent accessible name. Kept
inline, since a sprite sheet would be a build step.

## 8. JavaScript

Single `assets/js/site.js`, `defer`, no dependencies, target under 200 lines. Four
behaviours, each independently guarded so a failure in one cannot break another:

1. **Mobile nav** — toggle, `aria-expanded`, Esc, outside click, focus return.
2. **Lightbox** — delegated click on `[data-lightbox]`; builds the overlay, traps focus,
   closes on Esc/backdrop/close-button, restores focus to the originating thumbnail.
   Left/right arrows move through the gallery.
3. **Footer fire canvas** — the existing effect, tidied: `IntersectionObserver` pause when
   offscreen, `document.hidden` pause, no start under reduced motion.
4. **Reduced-motion video guard** — pauses autoplaying feature clips and shows posters.

Every one is an enhancement. `site.js` sets `data-js` on `<html>` as its first action, and
all JS-dependent hiding is scoped to `[data-js]`. So with JS disabled: the nav panel is
simply never collapsed and all links stay visible, `[data-lightbox]` anchors fall back to
opening the full image directly (they are real `href`s), the fire canvas is replaced by a
static flame glyph, and every video keeps its `controls` attribute.

## 10. Management tooling

### `STYLE.md`

The style guide, and the primary deliverable for "manageable through Claude":

1. **Design tokens** — full reference table with intended use per token.
2. **Components** — every class from §7 with a copy-paste HTML snippet and a note on when
   to use it.

4. **Voice and tone** — derived from existing copy: direct, warm, concrete, first-person
   plural, light exclamation. With do/don't examples.
5. **Recipes** — ordered, file-by-file:
   - Add a game — new page, home strip, nav, sitemap, OG image
   - Add a level to Kabonk!
   - Add or replace a screenshot

   - Remove a game — page, strip, assets, sitemap, inbound links
   - Change a colour or font — token-only edits

### `CLAUDE.md`

Operating instructions for future Claude sessions: repo map, the §2 constraints stated as
rules, where each piece of content lives, the deploy flow, a pre-commit checklist, and an

`.woff2`, `.svg`, `.xml`; directory-index resolution matching GitHub Pages; 404 falls
through to `404.html`. Run: `node tools/serve.js`.

## 11. Fernweh artwork

Fernweh has **no artwork of any kind** — no logo, no screenshots, no concept art. Per the
user's decision, we do not block on this.

The page and home strip are carried by a **CSS dusk scene**: layered gradients suggesting
horizon, treeline and campfire glow in the Fernweh palette, plus large display typography.
It is designed to look deliberate rather than placeholder.

The markup is shaped so real art drops in later as a one-line change: the scene lives
behind a single `.fernweh .hero__bloom` background declaration, replaceable with a
`url()`. STYLE.md documents this swap as a recipe.

## 12. Accessibility, SEO and performance

**Accessibility**
- Semantic landmarks: `header`, `nav`, `main`, `article`, `footer`. One `h1` per page,
  no heading levels skipped.
- Alt text on every image. Decorative art marked `alt=""`.
- Visible `:focus-visible` ring in `--accent`, never removed.
- Lightbox and mobile nav trap focus and restore it on close.
- All motion behind `prefers-reduced-motion`.
- Target: no WCAG 2.1 AA violations. Text contrast verified per §5.2.

**SEO** — the current site ships an identical description and an identical Kabonk!-Steam
OG image on all three pages, so **Fernweh currently previews as Kabonk! on social**. Fixed:
- Per-page `<title>`, `<meta name="description">`, `<link rel="canonical">`.
- Per-page OG and Twitter card tags with a page-appropriate image.
- `sitemap.xml` listing all public pages; `robots.txt` pointing to it.
- RSS autodiscovery in every head.

**Performance**
- Explicit `width`/`height` on every image to eliminate layout shift.
- `loading="lazy"` and `decoding="async"` below the fold; hero art eager.
- `preload="none"` on all video; posters on all video.
- Fonts preloaded, `font-display: swap`, latin subset only.
- One stylesheet, one deferred script. No render-blocking JS.

## 13. Acceptance criteria

1. `www` is an orphan branch containing only the new site.
2. `gh-pages`, `main` and `static-page` are byte-identical to their pre-work state.
3. The site renders correctly from `node tools/serve.js` at desktop, tablet and phone
   widths.
4. Home, Kabonk!, Fernweh, updates index, the seed post and 404 all render complete and
   readable **with JavaScript disabled**.
5. No network request leaves the origin — verifiable in the Network panel.
6. Every image has meaningful `alt`; every page has a unique title, description and OG
   image.
7. All links in §9 resolve; no internal link 404s.
8. Adding a Kabonk! level by following the STYLE.md recipe requires editing exactly one
   file plus adding one image.
9. Publishing an update by following the STYLE.md recipe touches exactly the four files
   the recipe names.
10. The deploy workflow succeeds and serves `sparkofchaos.com` from `www` once the user
    sets it as default.
